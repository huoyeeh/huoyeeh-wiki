## 1 大模型基础
### 1.1大模型到底是什么玩意
大模型全称**大语言模型（Large Language Model，LLM）**，是基于深度学习的巨型神经网络，以海量文本、图片、音视频数据做训练，学习人类语言、知识、逻辑、创作模式。
- **本质**：它是一个拥有海量参数的深度学习概率模型 。
- **工作机制**：它的核心任务非常直观——**根据你输入的上文，预测下一个最可能出现的 Token（字或词）** 。
- **如何变成“通才”**：尽管底层只是在做“文字接龙”，但当模型吞噬了全网数以万计的图书、网页、代码和论文后，它在做接龙的过程中被迫学会了语法、逻辑、编程、甚至人类的常识与推理能力。
### 1.2 大模型存在的意义
在大模型出现之前，传统的 AI 主要是**专才模式**（如分类模型、语音识别模型），一个模型只能做一件特定的事情。而大模型带来了以下革命性的改变：
- **从“专用”到“通用”（AGI 的曙光）**：大模型拥有极强的**泛化能力**，同一个模型既能写代码、做翻译，又能写诗、分析财务报表，无需针对每个场景重头开发模型。
- **涌现能力（Emergent Abilities）**：当模型规模突破一定临界点（通常在百亿参数以上）时，会突然展现出小模型根本不具备的能力，比如复杂的逻辑推理、上下文学习（In-Context Learning）和思维链（Chain of Thought）能力。
- **改变人机交互范式**：以前人要学习机器能听懂的指令/编程语言，现在机器可以直接理解人类的**自然语言**，极大地降低了技术门槛。
**AGI（Artificial General Intelligence，通用人工智能）** 就是 AI 发展追求的“终极目标”之一，俗称**像人一样聪明、甚至超越人类的全面型 AI**。
ANI（Artificial Narrow Intelligence，狭义/专用人工智能），**特点**：只能在**特定领域**打败人类，换个场景就完全失效。
**AGI（通用人工智能）**： **特点**：具备**跨领域的自主学习、逻辑推理、感知和执行能力**。
### 1.3 大模型参数
#### 1.3.1 参数
参数就是神经网络里面**大量的权重数值**，是模型学习完知识之后保存下来的 “记忆载体”。训练就是不断调整这一堆数字；推理就是用这些数字计算输出结果
- **参数的物理含义**：参数（Parameters）在数学上就是神经元之间连接的**权重（Weights）和偏置（Biases）**。你可以把大模型想象成一个包含数千亿个调节旋钮的巨大超级方程，每个“旋钮”对应一个浮点数值。
- **训练的本质就是调参**：在预训练阶段，AI 吐出错误预测时，系统会通过反向传播算法自动微调这几百亿/千亿个“旋钮”，直到它接龙的准确率达到最高。
![图片](./images/0b294270a5910db77bf8c6b55b0115e1.png)
单位：**B（Billion，十亿）**7B = 70 亿参数，13B=130 亿，70B=700 亿，千亿就是 1000B。
- **常见规模（如 7B/13B/70B）**：
    - **B（Billion）**：代表“十亿”。
    - **7B**：70 亿参数（通常需要约 14GB~16GB 显存来加载权重）。
    - **70B**：700 亿参数（需要多张高性能 GPU 才能加载并运行）。
#### 1.3.2 稠密和混合模型
稠密模型（Dense Model）**与**混合专家模型（MoE, Mixture of Experts）是大模型架构的两大主流设计路线。它们的核心区别在于：**每次处理数据时，是动用模型的“全员”参数，还是只激活其中的“一部分”专家。**
![图片](./images/0b897dce14329e5c411c49560c37fbbb.png)
1. 稠密模型（Dense Model）
运行机制：全员上阵。输入每一个 Token（字/词）时，模型中的所有参数都会参与计算。
代表模型：LLaMA 系列、GPT-3、Early GPT-4（早期版本）、DeepSeek-V1 稠密版等。
优缺点分析：
优点：结构简单标准，易于训练、部署和分布式调度；在参数量较小（如 7B、8B）时效率极高。
缺点：当模型规模扩展到千亿级（如 175B+）时，每次推理都要计算全部参数，算力成本（FLOPs）和延迟会呈爆炸式增长。
1. 混合专家模型（MoE Model）
运行机制：按需分工。将传统 Transformer 中的 前馈网络层（FFN）拆分成多个独立的“子网络”（即专家，Experts），并增加一个路由网络（Router/Gate）。
路由机制：当输入一个 Token 时，路由会分析这个 Token 属于什么类型（比如代码、数学还是普通对话），然后决定只把这个 Token 转发给最擅长的 1~2 个专家处理。
代表模型：Mixtral 8x7B、GPT-4（据传为 MoE）、DeepSeek-V2/V3 等。
核心优势：总参数量大，但计算量（FLOPs）极小。
例如：一个“总参数 47B”的 MoE 模型，如果每次只激活 2 个专家（激活参数仅 13B），那么它推理时的计算速度和算力消耗就等同于一个 13B 的稠密模型，但能力却接近 47B 的稠密模型。
#### 1.3.3 <span style="color:#1f1f1f">参数和 token</span>
**参数（Parameters）** 和 **Token** 是理解大模型计算与运维的两个最核心单位。简单来说：**参数决定了模型的“大脑容量”，而 Token 是模型用来“阅读和表达”的文本基本单位。**
. 深入对比：参数 vs Token
| **维度** | **参数 (Parameters)** | **Token** |
| --- | --- | --- |
| **通俗比喻** | 模型大脑里的**神经元/知识记忆体** | 模型的**词汇片段/文字计量单位** |
| **本质属性** | **静态的**（模型训练好后固定不变） | **动态的**（随着用户的输入和输出实时变化） |
| **计量单位** | B（Billion，十亿），如 7B = 70 亿参数 | 个数（Tokens），如 1 个 Token ≈ 0.75 个英文单词或 0.5~0.8 个汉字 |
| **显存影响** | 决定了模型**静态加载**所需的显存基础（如 7B 需要 ~14GB） | 决定了推理/训练时的**动态显存**（KV Cache）与计算时长 |
| **商业计费** | 决定了购买或部署 GPU 显卡的硬件成本 | 云厂商 API 调用的**计费标准**（如 ￥0.002 / 1k Tokens） |
Token 究竟是什么？
大模型并不像人类一样直接阅读“字”或“词”，而是通过 Tokenizer（分词器） 将输入的文本切分成一串数字向量（Token ID）。
切分规则：
英文中，learning 可能会被切分为 learn + ing（2 个 Token）。
中文中，常见的词如 人工智能 可能是 1~2 个 Token；罕见字或标点符号可能会占用更多 Token。
计算映射：通常 1 个英文 Token ≈ 4 个英文字符（约 0.75 个单词）；在中文大模型优化后，1 个中文 Token 通常对应 0.5 ~ 1 个汉字。
1000 token 中文大约等于 500‑700 个汉字。
在真实的部署和运维监控中，**参数**与 **Token** 共同决定了系统的性能与资源开销：
1. **计算吞吐（TPS, Tokens Per Second）**：
运维监控的核心指标之一就是每秒生成的 Token 数量。参数量越大的模型，每生成 1 个 Token 所需的浮点运算量（FLOPs）越高，推理延迟也越大。
1. **上下文窗口（Context Window）**：
大模型一次能处理的最大 Token 数量（如 8k、32k、128k Tokens）。输入的 Token 越多，模型在推理时保存的 **KV Cache 显存** 就会呈二次方（或线性，取决于注意力机制）暴涨。

### 1.4 Transformer原理
#### 1.4.1 Transformer核心架构
Transformer 架构及其核心的自注意力机制（Self-Attention）是大模型（LLM）实现理解与推理的**底层心脏**。
几乎所有现代大模型（稠密、MoE）底层骨架都是 **Transformer**，而**自注意力 (Self‑Attention)** 是 Transformer 最核心的灵魂。没有自注意力，就没有现在的大模型。
传统 RNN：文字必须一个接一个顺序算，前面算完才能算后面，长文本慢，长距离信息容易丢失。Transformer：**所有 token 可以并行计算**，依靠自注意力捕捉句子内部的关联关系。
#### 1.4.2 整体架构范式
标准的 Transformer 包含编码器（Encoder）**和**解码器（Decoder）两部分：
![图片](./images/8b70cc7cfeeaa126b264e2f54e397029.png)
- **Encoder-Decoder 架构**（如 T5）：Encoder 负责特征提取，Decoder 负责生成，常用于翻译任务。
- **Decoder-Only 架构**（如 GPT、Llama、DeepSeek）：大模型普遍采用的路线。带掩码的 Masked Self-Attention 确保计算时当前 Token 只能看到“左侧上文”，严格按照“自回归模式”预测下一个词。
1. **Encoder 编码器**：理解输入（翻译、BERT 用）
1. **Decoder 解码器**：逐字生成输出文本（GPT、LLaMA、Qwen 这类大语言模型**只用 Decoder**）
1. 我们日常用的生成式大模型，都是**纯 Decoder 架构**，一层一层堆叠，几十层、上百层。
每一层 Decoder 层内部包含两大组件：
1. 掩码自注意力（Masked Self‑Attention）
1. 前馈网络 FFN（Feed‑Forward Network）
> MoE 模型就是把 FFN 替换成混合专家层。
#### 1.4.3 核心心脏：自注意力机制（Self-Attention）
自注意力机制的核心原理是：**计算序列中每个 Token 与其他所有 Token 之间的相关性权重，并结合上下文重新编码每个词的含义。**
![图片](./images/df0b02a1b2614d4a86ceeefcc71c6e26.png)
#### 1.4.4 Q、K、V 三矩阵概念
输入文本映射为 Embedding 后，通过乘以三个可学习的权重矩阵，为每个词生成三个向量：
- **Query ($Q$)**：查询向量（“我想寻找什么上下文？”）
- **Key ($K$)**：键向量（“我包含什么特征供别人匹配？”）
- **Value ($V$)**：值向量（“我实际代表的语义内容是什么？”）
计算流程四步：
1. 每个 token 分别生成 Q、K、V
1. **Q 和所有 K 做点积** → 算出相似度分数：代表当前词和其它词相关性多高
1. 分数做缩放 + Softmax 归一化 → 变成 0‑1 之间的**注意力权重**，权重越高代表越重要
1. 用权重对 V 加权求和，得到自注意力输出向量
公式简写：\(\text{Attention}(Q,K,V)=\text{Softmax}\left(\frac{QK^\mathrm{T}}{\sqrt{d_k}}\right)V\)

#### 1.4.5  多头注意力（Multi-Head Attention）与前馈网络（FFN）
在 Transformer 的单个 Encoder/Decoder 模块内，除了基础自注意力外还包含两个关键设计：
- **多头注意力 (MHA)**：把 $Q, K, V$ 拆分为多个独立子空间（例如 8 个头）分别计算注意力，最后拼接输出。不同“头”关注不同维度的关系（如语法结构、逻辑代词指代等）。
- **前馈网络 (FFN)**：自注意力层主要负责 Token 间的沟通；紧接着的 FFN 层对每个 Token 独立进行非线性变换，负责**知识存储与特征升维**。负责 **单个 Token 内部的知识提取与特征升维**（Computation / Memory）。
#### 1.4.6 完整 Decoder 一层执行流程（纯 Decoder 大模型）
```bash
输入Token嵌入向量
    ↓
【掩码多头自注意力】→捕捉上下文词与词关系
    ↓ 残差连接 + LayerNorm归一化
【FFN前馈网络】（MoE此处替换为专家层）→做知识变换、推理计算
    ↓ 残差连接 + LayerNorm归一化
输出传给下一层Decoder

```
- **残差连接 Residual**：防止深层网络梯度消失，把原始输入直接加到输出上
- **LayerNorm 层归一化**：稳定训练，让数值分布可控
几十上百层这样的 Decoder 堆叠起来，就是完整大模型。最后经过输出层，预测**下一个 token 概率分布**，选概率最高的词输出，循环生成直到结束。
#### 1.4.7 生成答案为什么需要mask
**掩码自注意力（Masked Self-Attention）**：
- **职责**：负责 **Token 之间的信息沟通**（Communication）。
- **掩码的作用**：防止模型在生成第 $N$ 个词时“抄近道”看到第 $N+1$ 个词（即只能看上文，不能看下文）。

**核心概念总结**
| ******概念** | **作用** |
| --- | --- |
| Token | 输入的基本单位 |
| Embedding | 将 Token 转换为向量 |

| FFN | 对每个 Token 进行特征转换 |

| Decoder | 主要用于生成输出 |
一句话理解 Transformer
Transformer 先将文本转换为 Token 向量，然后通过 Self-Attention 计算每个 Token 与其他 Token 的关系，根据注意力权重融合上下文信息，再经过多层 Attention 和 FFN 不断提取更高层次的特征，最终完成理解或生成任务。
### 1.5 大模型的训练与统计数据
知识如何编码到参数中
#### 1.5.1 大模型的知识如何来的
大模型本身**没有真正记忆、不会思考**，所有知识全部来自数据 + 训练，知识存储在神经网络的**参数权重**里面。
**三个阶段（即大模型的三阶段训练范式）**：
预训练（Pre-training）—— 吸收知识（海量阅读）
指令微调（SFT, Supervised Fine-Tuning）—— 激活知识（对齐人类）
人类反馈强化学习（RLHF / DPO）—— 价值观与偏好对齐

#### 1.5.3 数据处理五大关键步骤
数据清洗、数据格式化、数据分词、数据混合、去重和判重。
#### 1.5.4 大模型调用数据（如何回答问题）
接收输入、组织上下文、预处理和编码、模型计算、逐个生产词元、后处理和安全检查、返回结果
```bash
[用户输入] ──► 1. 接收输入 (鉴权/限流)
                    │
                    ▼ 2. 组织上下文 (拼接 Prompt + 历史对话 + RAG 知识)
                    │
                    ▼ 3. 预处理和编码 (Tokenizer 分词 + Embedding + RoPE)
                    │
                    ▼ 4. 模型计算 (Prefill 阶段并行计算，构建 KV Cache)
                    │
                    ▼ 5. 逐个生产词元 (Decode 阶段自回归循环，结合 Temperature 采样)
                    │
                    ▼ 6. 后处理和安全检查 (Detokenization 转文本 + 敏感风控过滤)
                    │
                    ▼ 7. 返回结果 (SSE 流式推送 / 完整 JSON 响应) ──► [用户前端]
```


增加ollama用户
```
sudo useradd ollama  
sudo  mkdir -p /home/ollama

```
编辑service文件
创建服务文件 /etc/systemd/system/ollama.service ，内容如下：
```
[Unit]
Description=Ollama Service 
After=network-online.target  

[Service]
ExecStart=/usr/bin/ollama serve 
User=ollama 
Group=ollama 
Restart=on-failure 
Environment="OLLAMA_HOST=0.0.0.0:11434"  # 允许外部访问 

[Install]
WantedBy=default.target
```
启用并启动服务
```
sudo systemctl daemon-reload 
sudo systemctl enable ollama 
sudo  systemctl start ollama
```

### 2.5 vLLM方式部署
- 租用云主机（有本地硬件环境的同学，可以跳过）
我这里使用AutoDL，步骤略
- 安装vllm
参考文档 https://docs.vllm.ai/en/latest/getting_started/installation/gpu.html
注意，这里默认机器上已经有python3.12环境，如果没有需要先安装这个版本的python
创建虚拟环境
```
python3.12 -m venv /opt/vllm
source /opt/vllm/bin/activate
```
在这个虚拟环境里安装vllm
```
pip3 install "vllm>=0.17.0"  -i https://pypi.tuna.tsinghua.edu.cn/simple ##如果没有pip命令，需要先安装python3以及pip3
```
- 下载大模型
查看vllm所支持的大模型列表：
https://docs.vllm.ai/en/latest/models/supported_models/
在modelscope下载大模型
```
pip3 install modelscope -i https://pypi.tuna.tsinghua.edu.cn/simple #安装modelscope模块
```
下载大模型
```
mkdir -p /models/
modelscope download --model Qwen/Qwen3.5-4B --local_dir /models/Qwen3.5-4B
```
下载后的模型在： /models/Qwen3.5-4B
- vllm运行大模型
安装openai模块
```
pip3 install openai -i https://pypi.tuna.tsinghua.edu.cn/simple
```
运行模型
```
OMP_NUM_THREADS=4  vllm serve /models/Qwen3.5-4B --served-model-name Qwen3-4B --gpu-memory-utilization 0.95 --max-model-len 4096 --api-key sk-123456 --port 6006
```
说明：
--served-model-name Qwen2-7B # 指定模型名字，自定义的，不固定，调接口时使用
--gpu-memory-utilization 0.95 *# 提升显存利用率（默认0.9，最大建议0.95）*
--max-model-len 4096 *# 降低最大序列长度（根据需求调整）*
--api-key # 定义api key
--port 6006 # 自定义端口为6006，因为autodl 6006端口支持直接访问
- vllm其它用法
1）启用混合精度量化
```
vllm serve your_model_path  \
--dtype half \                  
--gpu-memory-utilization 0.9
```
说明：
--dtype half # 使用 FP16 半精度减少显存占用，显存需求降低约50%
2）分布式推理（多 GPU 并行）
```
# 在多 GPU 上分摊显存压力 
vllm serve your_model_path  \
--tensor-parallel-size 2 \ 
--gpu-memory-utilization 0.9
```
说明：
--tensor-parallel-size 2 # 使用2张GPU并行
3）启用模型量化（如 AWQ/GPTQ）
```
# 使用 AWQ 量化进一步压缩模型 
vllm serve your_model_path  \
--quantization awq \  
--gpu-memory-utilization 0.9
```
说明：
--quantization awq # 需模型支持量化格式
3）参数参考表
| 参数 | 典型值范围 | 作用说明 |
| --- | --- | --- |
| --gpu-memory-utilization | 0.8~0.95 | 显存利用率（过高可能导致 OOM） |
| --max-model-len | 2048/4096/8192 | 限制模型处理的最大序列长度 |
| --tensor-parallel-size | 1~8 | GPU 并行数量（需物理 GPU 支持） |
| --dtype | half/auto | 量化类型（显存敏感场景用 half） |

```
curl localhost:6006/v1/models   ##查看模型列表
```

```
nohup vllm serve /root/autodl-tmp/models/Qwen3.5-4B \
    --served-model-name Qwen3.5-4B \
    --distributed-executor-backend ray \
    --tensor-parallel-size 1 \
    --pipeline-parallel-size 2 \
    --max-model-len 32768 \
    --gpu-memory-utilization 0.90 \
```

参数说明：
- --distributed-executor-backend ray ： 分布式 worker 由 **Ray** 管理，告诉 vLLM 使用已经启动好的 Ray Cluster
- --tensor-parallel-size 1 / -tp 1 ： Tensor Parallel 数量， 每个 pipeline stage 使用 1 张 GPU
- --pipeline-parallel-size 2 / -pp 2 ： Pipeline Parallel 数量，把模型按层拆成 2 个 stage，分别运行在两张 GPU / 两个节点上
- --reasoning-parser qwen3 ： 解析 Qwen 的 reasoning/thinking 输出，使用 OpenAI API 时可把 reasoning 内容正确解析出来

通过不同任务、数据规模、计算资源和部署环节，对微调方法的要求不同。

- 资源有限但希望保持较好效果-- 参数高效微调
- 数据非常少-- 优先开了prompt方法或少样本学习
- 需要部署到手机、边缘设备- 知识蒸馏和模型压缩
