## **3 大模型微调**
大模型微调（FIne-tuning）是深度学习领域中一项关键技术，通过对预训练模型进行特定任务或领域的进一步训练，优化其性能以适应特定的应用场景。
### 3.1 搞懂大模型微调
#### 3.1.1 为什么需要微调
1. **适配领域专属知识**预训练数据是通用互联网数据，缺少行业专有术语、业务流程、内部知识库。直接提问，模型容易生成通用化回答，不懂行业业务；微调使用领域数据集，让模型学习行业专有知识。
1. **对齐业务指令与输出格式**业务场景往往有固定输出规范：比如 JSON 格式输出、固定问答模板、指定风格、角色设定。Prompt 提示词有上限，复杂业务仅靠提示词约束效果不稳定，微调可以把格式、角色、输出习惯固化进模型权重。
1. **降低推理成本**如果完全依靠长 Prompt 塞入大量业务示例，每次推理 token 开销大，速度慢、成本高。微调将业务知识内化到模型，推理阶段不需要携带大量示例，减少输入 token，提升推理速度。
1. **修正模型行为，对齐安全与偏好**可以通过微调修正模型回答倾向性，实现指令跟随、拒绝不当提问、输出符合企业规范，包含 SFT 监督微调、RLHF 人类反馈强化学习都属于该范畴。
#### 3.1.2 微调技术分类
**按参数更新范围分类**
##### 1.全参数微调（full fine-tunning）
- 原理：加载完整预训练模型，训练时**更新模型全部权重参数**。
- 优点：理论效果上限最高，全部参数参与学习，对领域数据拟合能力强。
- 缺点：
    - 显存消耗巨大，大参数量模型需要多卡 A100/H100 等高端算力；
    - 训练产出完整新模型权重，存储开销大；
    - 容易发生灾难性遗忘：把预训练学到的通用能力覆盖丢失。
- 适用场景：小参数量模型、拥有充足算力、高质量大规模领域数据集。

**按训练数据和学习目标分类**
1. **SFT 监督微调（Supervised Fine‑Tuning）**使用人工标注好的 {指令‑回答} 数据集做有监督训练，教会模型遵循指令输出指定结果，是微调基础环节。
1. **RLHF 人类反馈强化学习**分为 SFT → 奖励模型训练 RM → PPO 强化学习三步，用人类打分反馈，优化模型输出偏好，提升回答质量。算力要求极高。
1. **DPO 直接偏好优化**RLHF 的轻量化替代方案，不需要单独训练奖励模型，直接使用偏好数据集训练，实现人类偏好对齐，工程落地越来越常用。
1. **继续预训练（Continued Pre‑training）**使用大量无标注领域文本，像预训练阶段一样继续做 next‑token 预测，注入领域知识，一般作为微调前置步骤。

### 3.2 大模型开源微调工具
#### 3.2.1 hugging face transformers -PEFT
Hugging Face Transformers 是开源 Python 库，内置数千种预训练模型（GPT、T5、Qwen、DeepSeek 等），支持 NLP、计算机视觉、音频多模态任务。**核心优势**
1. **模块化设计**：Pipelines、Tokenizer、模型加载保存组件，少量代码即可完成文本生成、分类。
1. **跨框架支持**：兼容 PyTorch、TensorFlow、JAX，框架之间可切换。
1. **社区资源**：Hugging Face Hub 托管海量开源模型、数据集，方便部署协作。
PEFT（Parameter‑Efficient Fine‑Tuning 参数高效微调）
Hugging Face 开发，面向大模型，用很低算力完成下游任务适配。
工具属性
属于 HF 生态工具包，支持 LoRA、Prefix Tuning 等算法；**冻结模型绝大多数参数，只更新少量新增 / 特定参数**完成任务适配。
解决的核心问题
1. 资源限制
> 示例：3B 模型全参数微调显存约 47GB；PEFT 仅需 14.4GB。全量微调要更新数十亿参数，显存、算力开销巨大；PEFT 大幅降低硬件门槛。
1. **灾难性遗忘**冻结主干预训练权重，保留模型原有通用能力，避免微调把基础能力 “学丢”。
| 方法 | 原理 | 适用场景 |
| --- | --- | --- |
| **LoRA** | 向冻结的权重矩阵注入**低秩矩阵**，只训练新增的小矩阵（典型秩 r=8） | NLP、多模态任务 |
| **Prefix Tuning** | 在输入层 / 每一层前面，增加一组可学习的连续前缀向量，引导模型输出适配任务 | 文本生成、分类任务 |
| **QLoRA** | LoRA + 4bit/8bit 量化技术，进一步降低显存占用 | 消费级家用 GPU 训练大模型 |
核心要点速记
1. **LoRA**基座模型权重**完全冻结**，不改动；只训练两个很小的低秩矩阵 A、B。训练完保存的只有 LoRA 适配器（几十 MB），推理时可以合并到原模型。r（秩）是关键超参数，r 越大，可学习参数越多，效果越好，但开销上升。
1. **Prefix Tuning**不修改模型权重，给每一层增加虚拟的可学习前缀 token 向量。缺点：会占用一部分上下文窗口长度；适合生成、分类。
1. **QLoRA**LoRA 的增强版本，把基座模型做 4/8bit 量化压缩，在消费级显卡（比如 RTX3090/4090）就可以微调几十 B 的大模型，**几乎不损失效果**，是个人、小团队最常用方案。

### 3.4 微调数据集分类
大模型微调数据集的分类，用来微调大模型的数据集合。专门准备好的数据，用来教一个很聪明的模型变得更擅长某些特定任务。
业界没有严格的分类，主要有几大类
#### 3.4.1 指令跟随
- 格式：(instruction指令，input输入，output输出) 三元组
- 作用：训练模型听从人类指令完成任务
- 适用：文本生成、翻译、问答
- JSON 示例
#### 3.4.2 多轮对话
- 特点：携带完整对话上下文历史
- 作用：训练模型多轮交互、对话连贯性
- 适用：聊天机器人、智能客服等交互业务场景
#### 3.4.3 思维链
- **定义**：带推理过程的数据集，训练模型不光输出最终答案，还要输出逻辑推导步骤，学会**分步思考**。
- **适用场景**：复杂逻辑推理、数学计算、数学证明、代码调试；代表推理模型：DeepSeek‑R1。
```
[
  {
    "instruction": "解决数学应用题",
    "input": "小红买了4个苹果，每个3元；又买了2瓶牛奶，每瓶比苹果贵5元。总花费多少？",
    "chain_of_thought": [
      "苹果单价：3元/个 → 4个总价：4×3=12元",
      "牛奶单价：3+5=8元/瓶 → 2瓶总价：2×8=16元",
      "合计花费：12+16=28元"
    ],
    "output": "总花费为28元"
  }
]

```

- **定义**：通过标注数据训练模型对文本进行类别预测或标签分配，让模型理解文本语义与类别特征的关系。
- **适用场景**：需要结构化输出的场景，如情感分析、新闻分类、意图识别等。

#### 3.5.1 Alpaca 格式
两种形态：完整 JSON 数组文件，或者拆成 JSONL。
| 字段 | 说明 |
| --- | --- |
| instruction | 指令 / 用户提问（必填） |
| input | 可选，补充输入上下文，没有填空字符串"" |
| output | 模型期望输出回答（必填） |
```json

    "instruction": "解释什么是大模型微调",

- 适用：单轮问答、指令微调，早期 LLaMA 微调广泛使用。

#### 3.5.2 shareGPT格式
来源于 ShareGPT 开源对话数据集，**多轮对话标准**。**字段**
表格
| 字段 | 说明 |
| --- | --- |
| conversations | 数组，存放一轮轮对话 |
| from | 角色：human 用户；gpt AI 助手 |
| value | 对话文本内容 |
```
{
  "conversations": [
    {"from": "human", "value": "什么是JSONL？"},
    {"from": "gpt", "value": "JSONL是逐行JSON格式，每行一条数据。"},
    {"from": "human", "value":"和普通JSON区别是什么？"},
    {"from": "gpt", "value":"JSONL每行独立JSON，支持流式读取。"}
  ]
}

```
- 适用：**多轮对话微调**，历史大量开源对话数据集。
- 注意：角色固定 human / gpt；对话必须交替出现，不能连续两条 human。
- Llama‑Factory、Axolotl 原生支持。
#### 3.5.3 ChatML格式
结构：基于OpenAI的chatML格式，使用特殊标记；；来划分角色和消息。
用途：广泛用于对话模型微调，支持多角色交互。
特点：结构清晰，易于扩展，支持系统提示。
特殊标记<|im_start|>、<|im_end|>划分 system/user/assistant 角色
#### 3.5.4 LLaMA-factory
JSON/JSONL，dataset、conversations / instruction
通用框架格式，兼容对话、分类、生成多类任务，灵活性高
#### 3.5.4 JsonL
这是**存储载体，不是任务格式**，上面所有数据集大多封装在 JSONL 里。
- 文件后缀：.jsonl
- 规则：文件**每一行是独立 JSON 对象**，行之间换行分隔，**整个文件外面不要加 ****[ ]**
- 优点：支持流式读取，不用一次性加载全部数据，百万级数据集不会 OOM
- 错误写法（❌）：把全部对象放到数组[]里面
- 单轮指令任务 → **Alpaca**
- 多轮聊天对话 → **ShareGPT / ChatML**
- 推理数学逻辑任务 → **ORCA**
- 偏好对齐、RLHF 替代 → **DPO**
- 使用 LLaMA‑Factory 框架训练 → **LLaMA‑Factory 格式**

### 3.9 微调超参
超参数（hyperparameters）：训练**开始前手动设置**，不是模型训练学出来的权重，控制整个训练流程；不会保存进模型权重文件，训练完成后无法从模型里反向推导。
#### Number of Epochs 迭代轮次
**Epoch 含义**：模型把全部训练数据集完整过一遍 = 1 个 epoch。
示例：训练集 10000 条样本，设置num_train_epochs=3👉 模型完整读取全部 10000 条样本，一共学习 3 轮。
##### Epoch 大小带来的影响
1. Epoch 设置过小
- 数据学习不充分，**欠拟合**
- 任务效果差，模型没有学会领域知识
1. Epoch 设置过大
- 死记硬背训练集样本，**过拟合**
- 在训练集 loss 很低，但是新问题推理效果很差，**泛化能力下降**
> ✅LLM 微调经验：
- LoRA/QLoRA SFT 监督微调：**3‑5 epoch 最常用**；小数据集 (几百‑2k 条) 优先取小值，防止过拟合；
- 全参数微调：一般 2‑4 epoch。
> 没有万能固定值，**依靠验证集 loss、loss 曲线图、实际对话效果综合判断**，不要只看训练 loss。
#### Learning Rate 
学习率是大模型微调**最重要超参数**。含义：每一轮参数更新时，权重调整的幅度；通俗理解：模型学习的时候，每一步向前迈多远。
##### 学习率过高
- 参数更新幅度太大，跨过最优解
- loss 剧烈震荡，上下跳动
- 损失无法下降，**训练不能稳定收敛**
##### 学习率过低
- 参数改动很小，学习进度很慢
- 训练耗时拉长，需要更多 epoch
- 容易欠拟合，学不会新领域任务
##### LLM 微调经验取值
表格
| 微调模式 | 学习率参考 |
| --- | --- |
| LoRA SFT | 5e‑5 ~ 1e‑4 |
| QLoRA 4bit | 1e‑4 ~ 2e‑4 |
| Full 全参数微调 | 5e‑6 ~ 1e‑5 |
> 超参数不能死记硬背，实际调参需要综合：**数据规模、模型大小、batch‑size、微调方式**，通过实验迭代调优。
#### 损失函数概念
损失函数是深度学习数学函数，用来**量化模型输出结果和标准答案（ground truth）之间的差距**。模型训练的核心目标：**最小化 loss 损失值**，反向驱动参数更新，让模型输出越来越贴近真实答案。
#### 通俗类比
把训练当成学生做练习题：
1. 训练数据 = 练习题；标准答案 = 真实标签
1. 损失函数 = 老师给试卷打的分数
- loss 低（90/100）：模型输出接近标准答案，掌握较好
- loss 高（30/100）：模型输出偏差很大，错误多，需要修正
1. 根据 loss 大小，反向调整模型权重，相当于老师指出错题，告诉学生怎么修改做题思路。
#### 微调中损失函数的 3 个实际作用
1. **量化错误**充当尺子，用数字衡量模型生成内容和正确答案之间差距，衡量文本生成错误程度。
1. **指导优化方向**根据 loss 大小反向计算梯度，告诉模型每一个权重应该调大还是调小，一步步降低错误。
1. **收敛信号**当 loss 几乎不再继续下降，代表模型学习接近饱和，不需要继续训练；
> 注意：要看**验证集 loss**，不是只看训练集 loss；训练 loss 持续下降、val loss 抬升，代表过拟合。
#### Batch Size（批大小）
> 含义：**一次权重更新之前，模型一次性处理多少条训练样本**。例：batch_size=8，一次性读取 8 条样本，计算损失之后，执行一次参数更新。
##### 两种选择带来的影响
1. 大批量（大 batch）
- 优点：训练速度更快，梯度更加平稳
- 缺点：占用显存更高；梯度更新比较粗糙，精细学习能力变弱
- 风险：GPU 显存溢出 OOM 报错
1. 小批量（小 batch）
- 优点：显存占用低；参数更新更精细，泛化效果通常更好
- 缺点：训练速度变慢
> 💡显存不够的解决方案：**梯度累积 gradient_accumulation_steps**不需要调大真实 batch，累积多步梯度之后再更新权重，等价放大有效 batch 大小。有效批次 = per_device_train_batch_size × gradient_accumulation_steps × 显卡数量
示例：16GB 显存 GPU，文本任务 batch=16 比较均衡；强行设置 128 极易 OOM，同时更新粗糙。
#### Max Sequence Length（最大序列长度，cutoff_len）
> 含义：模型单次输入 + 输出允许的最大 token 总数。例：max_sequence_length=4096，整条样本（prompt+answer）总 token 不能超过 4096，超出部分直接截断丢弃。
##### 影响
1. **显存消耗**：序列越长，显存占用会显著上涨；
1. **训练速度**：长度越大，单步训练耗时越高；
1. **长文本处理能力**：设置足够大，才能学习长上下文问答；设置过小，样本会被截断，丢失问答内容。
> 实操经验：
- Qwen‑7B 日常领域 SFT：2048 / 4096二选一；
- 如果你的样本普遍短，就用 2048 节省显存；业务是长文档问答，调高到 4096。
> ⚠️注意：max_seq_len 不能超过模型原生支持的上下文窗口。
---
#### LoRA Alpha
> LoRA Alpha：LoRA 权重的**缩放系数**，控制 LoRA 分支对原始基座模型的影响强度。一般和 LoRA Rank (r) 配对使用。
##### Alpha 取值带来的影响
##### Alpha 设置较大
- LoRA 微调带来的改动对原模型影响更强
- 更容易学会新领域、新任务
- 副作用：训练稳定性下降，容易出现生成乱码、输出异常
##### Alpha 设置较小
- 对基座模型改动幅度弱，保留基座模型原有能力更多
- 生成输出更加稳定
- 副作用：学习新任务能力不足，领域知识学不到位
##### 工程实践惯例
行业通用做法：**保持 ****alpha = 2 × r****，也就是 alpha/r = 2**，维持比例稳定，平衡学习能力与训练稳定性。
示例配对：
1. r = 8，alpha = 16 （最常用基线）
1. r = 16，alpha = 32
> 补充理解 Rank (r)：r 代表 LoRA 低秩矩阵的秩，r 越大，可学习参数越多，表达能力越强；r 越小参数量越少，但表达能力受限。r=8 / 16：绝大多数领域 SFT 首选r=4：小数据集，追求极小参数量；表达能力弱
> 注意：不是 r 和 alpha 越大效果就一定越好，过大容易过拟合，同时会污染基座模型原生能力。

    --lora_dropout 0 \

```
说明：
- --stage : 指定训练阶段，微调的话就指定sft
- --finetuning_type lora：使用LoRA方法，节省显存
- --dataset：数据集名称
- --output_dir：模型保存路径
- --bf16：使用半精度，如果你的GPU不支持BF16，也可以使用FP16，但BF16效果更好
- --per_device_train_batch_size ：表示每个设备（GPU或CPU）在一次训练迭代中处理的样本数量，也就是所谓的“批次大小”，控制每个设备上的批次大小，直接影响显存、训练速度和模型效果，批次大小直接影响显存使用。批次越大，显存需求越高。如果显存不足，程序可能报错（如“CUDA out of memory”）
- --gradient_accumulation_steps ：表示梯度累积的步数。它用于在显存不足的情况下模拟较大的批次大小（batch size），从而平衡训练效率和模型性能。在显存受限时模拟大批量训练，若设置过大可能导致收敛变慢或效果变差，建议根据数据集和模型实验（如从 4 到 16 逐步调整）
- --num_train_epochs ：控制模型遍历训练数据集的次数，通常设为 1.0 到 5.0，根据数据集大小和任务需求调整。建议结合损失曲线或验证集性能优化设置
- --learning_rate ：设为 5e-5（即 0.00005），适合LoRA微调Qwen3等大模型的监督微调（SFT）任务
- --val_size ：随机从数据集中抽取多少比例的数据作为验证集，0.1就是10%
- **显存调整**：如果显存不足，减小per_device_train_batch_size（如1）或增加gradient_accumulation_steps（如16）。

**5、编辑微调脚本**
```
cd ~/train
cat > train.py <<EOF 
import torch
from datasets import load_dataset
from unsloth import FastLanguageModel
from unsloth.chat_templates import get_chat_template, train_on_responses_only
from trl import SFTTrainer, SFTConfig

# =========================
# 1. 基本配置
# =========================
MODEL_NAME = "/models/Qwen3-4B"
TRAIN_FILE = "./dataset/train_900.jsonl"
OUTPUT_DIR = "./outputs"
LORA_DIR = "./qwen3_q3lab_lora"
MAX_SEQ_LENGTH = 1024

# =========================
# 2. 加载4bit基础模型
# =========================
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=MODEL_NAME,
    max_seq_length=MAX_SEQ_LENGTH,
    load_in_4bit=True,
    load_in_8bit=False,
    full_finetuning=False,
)

tokenizer = get_chat_template(
    tokenizer,
    chat_template="qwen3-instruct",
)

# =========================
# 3. 添加LoRA
# =========================
model = FastLanguageModel.get_peft_model(
    model,
    r=32,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_alpha=32,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
    random_state=3407,
    use_rslora=False,
    loftq_config=None,
)

# =========================
# 4. 读取并格式化数据
# 数据格式：
# {"messages":[
#   {"role":"user","content":"..."},
#   {"role":"assistant","content":"..."}
# ]}
# =========================
dataset = load_dataset(
    "json",
    data_files=TRAIN_FILE,
    split="train",
)

def format_example(example):
    text = tokenizer.apply_chat_template(
        example["messages"],
        tokenize=False,
        add_generation_prompt=False,
    )
    return {"text": text}

dataset = dataset.map(
    format_example,
    remove_columns=dataset.column_names,
)

print("训练样本数：", len(dataset))
print("第一条格式化结果：")
print(dataset[0]["text"])

# =========================
# 5. 创建训练器
# =========================
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    args=SFTConfig(
        output_dir=OUTPUT_DIR,
        dataset_text_field="text",
        max_length=MAX_SEQ_LENGTH,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=8,
        num_train_epochs=3,
        learning_rate=1e-4,
        warmup_ratio=0.05,
        logging_steps=5,
        save_strategy="epoch",
        save_total_limit=2,
        optim="adamw_8bit",
        weight_decay=0.001,
        lr_scheduler_type="linear",
        seed=3407,
        report_to="none",
    ),
)

# 只计算assistant回答部分的loss
trainer = train_on_responses_only(trainer)

# =========================
# 6. 开始训练
# =========================
trainer.train()

# =========================
# 7. 保存LoRA
# =========================
model.save_pretrained(LORA_DIR)
tokenizer.save_pretrained(LORA_DIR)

print(f"\n训练完成，LoRA已保存到：{LORA_DIR}")
EOF
```

import gc
import torch
from pathlib import Path
from unsloth import FastLanguageModel

BASE_MODEL = "/models/Qwen3-4B"
FT_MODEL = "./qwen3_q3lab_lora"
PROMPT_FILE = "./dataset/ab_test_prompts.txt"
RESULT_FILE = "./ab_result.txt"

def load_prompts():
    lines = Path(PROMPT_FILE).read_text(encoding="utf-8").splitlines()
    prompts = []
    for line in lines:
        line = line.strip()
        if not line:
            continue
        if ". " in line and line.split(". ", 1)[0].isdigit():
            line = line.split(". ", 1)[1]
        prompts.append(line)
    return prompts

def run_model(model_name, prompts):
    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name=model_name,
        max_seq_length=1024,
        load_in_4bit=True,
    )

    answers = []
    for prompt in prompts:
        messages = [{"role": "user", "content": prompt}]
        text = tokenizer.apply_chat_template(
            messages,
            tokenize=False,
            add_generation_prompt=True,
        )
        inputs = tokenizer(text, return_tensors="pt").to("cuda")

        with torch.inference_mode():
            outputs = model.generate(
                **inputs,
                max_new_tokens=256,
                do_sample=False,
            )

        new_tokens = outputs[0, inputs["input_ids"].shape[1]:]
        answer = tokenizer.decode(new_tokens, skip_special_tokens=True)
        answers.append(answer.strip())

    del model
    del tokenizer
    gc.collect()
    torch.cuda.empty_cache()
    return answers

prompts = load_prompts()

print("正在测试基础模型...")
base_answers = run_model(BASE_MODEL, prompts)

        f"""==================== {i} ====================

【基础模型】
{base}

【微调模型】
{ft}
"""
    )
